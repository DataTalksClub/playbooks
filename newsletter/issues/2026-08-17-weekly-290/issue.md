## 150M Model Sets a New Cost-Performance Frontier

Better reasoning usually means larger models and more compute. Pathway’s BDH-CQ model sets a new cost-performance frontier on the ARC-AGI-1 benchmark that measures model reasoning.

It has only 150 million parameters and costs $0.0007 per task, up to 2,000 times less than other benchmarked models available on the market.

How you can use it:

- Define new tasks through examples instead of fine-tuning
- Adapt one compact base model to different tasks
- Make reasoning-heavy workloads much cheaper to run

Learn how BDH-CQ replaces costly reasoning traces with recurrent reasoning in a latent state.

[Explore BDH-CQ](https://pathway.com/blog/pathway-150m-model-breaks-arc-agi-1-cost-efficiency-frontier)

## Running Durable Agents in Production

Most agents run cleanly in a demo and then break the first time something goes wrong in production. The agent logic was never the hard part. Keeping it running reliably is.

In this workshop, Nicholas Lotz shows how to turn a working agent loop into a durable production workflow that can pause, recover, retry, and keep a full execution history.

You'll learn how to:

- Persist agent state outside the running process, so a crash doesn't lose progress
- Resume execution after crashes or interrupted deployments
- Retry flaky tool calls with timeouts and recovery logic
- Add human approval steps and more!

By the end, you'll understand the execution layer that separates a clever agent demo from a reliable agent service.

## Alexey on Data Newsletter: How to Do Evals in 2026

In the latest edition of the newsletter, Alexey shared his approach to agent evaluation.

Read the full edition to learn the eight steps for checking your agent's performance:

1. Start manually by “vibe-checking” the system, but also collect logs as early as possible
2. Create a tool for labeling the logs and put together a gold standard dataset
3. Create a judge that’s aligned with our judgment
4. Break the agent like a QA engineer
5. Get more data by generating it synthetically
6. Start collecting data from real users
7. Monitor your system with online evaluation
8. Always refine your gold standard dataset
