# Campaign Strategy

Use this reference to decide which event-promotion stage to run and how the stages hand off to each other.

Channel planning depends on whether the event is course-related or a general DataTalks.Club event. When channels, posting schedule, or distribution plan matter, read `channels.md`.

## Two-Stage Model

DataTalks.Club event promotion has two stages because the source material changes after the event.

Stage 1 happens before the event. It uses:

- Event description.
- Tool, product, or sponsor description.
- Speaker description.
- Registration link.
- Any approved pre-event claims or assets.

Read `stage-1-pre-event.md` for Stage 1.

Stage 2 happens after the event. It uses:

- Recording.
- Transcript.
- Notes.
- Slides.
- Code or demo links.
- Audience questions.
- Speaker follow-up notes.
- Timestamps or candidate clip moments.

Read `stage-2-post-event.md` for Stage 2.

Channel planning can apply to either stage. Use `channels.md` to map content pieces to timing, links, and distribution channels.

## Stage Selection

If the user provides only event/tool/speaker material, run Stage 1. Do not write recaps, recording-based takeaways, repurposed text posts from the event, or short-video ideas from the event recording. Include a Stage 2 handoff note describing what to collect after the event.

If the user provides recording, transcript, notes, slides, Q&A, timestamps, or post-event takeaways, run Stage 2. Do not recreate the pre-event announcement campaign unless the user asks for a full lifecycle package or retrospective.

If the user provides both pre-event and post-event material, the agent may run both stages, but the output must keep Stage 1 and Stage 2 separate. Do not mix pre-event speculation with post-event takeaways.

If the user asks for "everything" before the event, produce Stage 1 plus a Stage 2 plan. Explain that Stage 2 assets require the recording, transcript, notes, or other post-event source material.

## Campaign Principle

The goal is not to repeatedly announce the same event. Build a campaign that gives readers useful information even if they do not immediately register or watch the recording.

Across both stages:

- Announce the event clearly before it happens.
- Remind people shortly before it happens.
- For course-related events, create pre-event educational posts around problems the event addresses.
- For general events, default to announcement and reminder before the event, then create educational posts from the recording or notes after the event.
- Use either the product or the speaker's expertise to connect those problems to the event.
- After the event, recap what happened and repurpose the strongest ideas from the notes, transcript, or recording.

## Avoiding Repetition

Treat all assets as one campaign. Do not repeatedly use the same:

- Opening.
- Problem.
- Speaker biography.
- Product description.
- Feature list.
- Event description.
- Learning outcome.
- CTA wording.

Some event information will naturally repeat, especially the event title, date, speaker, recording link, and registration link. The surrounding argument should change.

Each educational or repurposed post should answer a different question, such as:

- Why does this problem happen?
- Why does the common solution fail?
- How does a particular technical approach work?
- What did the speaker explain or demonstrate in practice?
- What did the Q&A reveal about the audience's problem?

## Shared Quality Check

Before returning a campaign or assets, check that:

- The requested stage matches the available source material.
- Stage 1 assets do not claim post-event takeaways.
- Stage 2 assets use actual notes, transcript, recording, slides, Q&A, or speaker follow-up material.
- Each post has a distinct core argument.
- All factual claims are supported by supplied material.
- The event is connected naturally to the educational content.
- CTAs accurately describe what people can do next.
- Short-video ideas identify a self-contained moment and include timestamps when available.
- The separate DataTalks.Club style guide is applied when provided.
