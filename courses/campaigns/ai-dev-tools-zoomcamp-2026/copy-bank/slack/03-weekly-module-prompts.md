# Weekly Module Prompts

Use one prompt per module week after the automatic module announcement has already reached Slack.

## Module 1: AI-Native Workflow Design

Module 1 question:

Which part of your workflow made the agent's work easiest to execute and independently verify?

Please include:

- The requirement or backlog task.
- Its acceptance criteria and boundaries.
- The durable context you provided.
- The implementation role and the independent QA check.
- What failed, looped back to implementation, or required a human decision.

The most useful answers are concrete. "The agent did well" is less helpful than "the task passed the API tests but QA returned it because it missed an accessibility acceptance criterion."

## Module 2: End-to-End Workflow

Module 2 is where AI-assisted development becomes more realistic.

Where is your biggest friction right now?

- Frontend/backend integration.
- OpenAPI spec.
- FastAPI backend.
- Database.
- Tests.
- Docker Compose.
- Deployment.
- CI/CD.
- Understanding what the AI tool changed.

Reply with the area and one specific blocker. If you have a repo, include the link.

## Module 3: MCP

MCP can feel abstract until you inspect what is actually being sent and called.

This week, try to answer one question:

What context or tool would make your own coding workflow easier?

Examples:

- Search project docs.
- Query a local database.
- Summarize pull requests.
- Open issues from a repo.
- Fetch current documentation.
- Publish or update content.

Reply with one workflow idea. It does not need to be complicated.

## Module 4: Building an Agent

Module 4 goes into how coding agents work.

Good discussion question:

If you were building a coding agent for your own project, which tools would you give it first?

Possible tools:

- Read files.
- Search files.
- Write files.
- Run tests.
- Run linters.
- Inspect the file tree.
- Query docs.
- Open pull requests.

Also mention which tool you would restrict or require approval for.

## Module 5: Testing, CI/CD, and DevOps

Module 5 question:

Where could AI help your project without weakening the engineering checks?

Good candidates:

- Drafting tests.
- Summarizing pull requests.
- Suggesting risky changes.
- Writing release notes.
- Explaining CI failures.
- Drafting deployment notes.
- Reviewing logs or incident notes.

The important part is the check. What command, test, review, or approval still needs to happen?

## General Weekly Check-In

Weekly check-in:

What did you finish this week, and what is still unclear?

Use this format:

- Finished:
- Stuck on:
- Next step:

If you are behind, that is fine. A clear next step is more useful than trying to catch up on everything at once.
