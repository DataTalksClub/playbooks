## Do I Need Paid Tools?

You do not need to use one specific paid tool for the whole course.

The course covers several tools and workflows. Some tools may have free-tier limits, and some optional workflows may use API keys or paid services.

The main skill is learning how to specify work, give agents durable context, separate implementation from independent QA, and keep human decisions and review central.

## I Am New to AI Coding Tools

Prior AI coding tool experience is not required.

You should be comfortable with:

- Basic programming.
- Command line.
- Git and GitHub basics.
- Reading and debugging code.

Start with Module 1 and focus on the workflow: specification, backlog tasks, durable context, implementation, independent QA, and human review. You do not need to master every tool at once.

## I Do Not Know Web Development

Web development experience is not required, but the course includes frontend/backend integration.

Use the materials, AI tools, and Slack questions to work through unfamiliar parts. The goal is not to become a frontend specialist in one week. The goal is to learn how AI tools can help you build and inspect a working application.

## My AI Tool Produced Broken Code

This is expected sometimes.

Useful next steps:

1. Run the app or tests.
2. Copy the exact error.
3. Identify which file changed.
4. Ask the tool to explain the failure before asking for a fix.
5. Apply the smallest fix.
6. Re-run the command.
7. Commit only after you understand the change.

If you ask in Slack, include the command, error, and repo link.

## I Am Behind

Being behind is common in live cohorts.

Pick one next action:

- Finish the current module setup.
- Run one example.
- Submit the best homework version you can.
- Start a small final project skeleton.
- Write a README for what already works.

Trying to catch up on everything at once usually makes it harder to restart.

## Please Do Not Share Full Solutions

Please avoid posting complete homework solutions in the main channel.

Helpful alternatives:

- Explain the debugging step.
- Point to the relevant docs.
- Share a smaller snippet.
- Ask a guiding question.
- Describe how you found the issue.
