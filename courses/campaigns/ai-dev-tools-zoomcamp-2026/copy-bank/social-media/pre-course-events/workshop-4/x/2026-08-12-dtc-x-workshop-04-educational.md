# Thread

## Post 1

Passing tests and deploying automatically are important. They still do not answer the production question:

Is the app working for users right now?

## Post 2

Good observability connects the symptom to evidence. A failed request should be visible through a metric, a trace, and a log that all point to the same event.

## Post 3

An alert should include the deployed version, dashboard link, and runbook, not just a vague warning.

## Post 4

For AI-built apps, there is another question: can a coding agent help investigate without getting production access?

## Post 5

Workshop 4 will show one practical answer: bounded evidence packets, Codex or Claude Code headless as a read-only investigator, action allowlists, autonomy levels, and authorization outside the model.
