# Post

Passing tests and deploying automatically are important. They still do not answer the production question:

Is the app working for users right now?

Good observability connects the symptom to evidence. A failed request should be visible through a metric, a trace, and a log that all point to the same event. An alert should include the deployed version, dashboard link, and runbook, not just a vague warning.

For AI-built apps, there is another question: can a coding agent help investigate without getting production access?

Workshop 4 of AI Dev Tools Zoomcamp will show one practical answer. Alexey will collect a bounded evidence packet, run Codex or Claude Code headless as a read-only investigator, and keep authorization outside the model with action allowlists and autonomy levels.
