# Post

A deployed app needs evidence you can use during an incident.

For one important endpoint, a failed request should connect to:

- A metric that shows the symptom
- A trace that shows where the request went
- A log that explains what happened
- A deployed version
- A runbook

This is much more useful than a dashboard full of generic CPU graphs.

For AI-built apps, the next question is how to involve a coding agent safely. The agent can help collect evidence and rank hypotheses, but it should use allowlisted read-only queries and a fixed schema. It should not receive production credentials.

Workshop 4 of AI Dev Tools Zoomcamp will show this workflow with OpenTelemetry, Prometheus, Loki, Tempo, Grafana, alerting, runbooks, evidence packets, and read-only agent investigation.
