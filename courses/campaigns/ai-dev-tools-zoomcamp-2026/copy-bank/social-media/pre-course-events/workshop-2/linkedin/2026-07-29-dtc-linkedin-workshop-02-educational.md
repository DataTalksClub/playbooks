# Post

A useful AI-assisted development loop has four steps:

1. Define what should happen.
2. Ask the AI tool to implement it against explicit project context.
3. Review and test the result.
4. Save the accepted decisions in a form the next task can use.

The fourth step is easy to miss.

If the product requirements, API behavior, and test expectations exist only in chat, the next generated change may follow a different set of assumptions.

Documents such as a product spec, acceptance criteria, OpenAPI contract, and tests give the project persistent context. They also give the developer something concrete to inspect when the application behaves differently from what was intended.
