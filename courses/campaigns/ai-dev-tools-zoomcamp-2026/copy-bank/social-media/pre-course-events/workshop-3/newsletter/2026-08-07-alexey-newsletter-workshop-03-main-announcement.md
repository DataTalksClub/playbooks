## Extending a coding agent around your project

On August 17, I am running the third free workshop for AI Dev Tools Zoomcamp 2026:

Coding Agent Capabilities: MCP, Skills, Plugins, and Custom Agents

Coding agents now have many extension points. We can give them repository instructions, connect them to tools through MCP, package reusable workflows as skills or commands, delegate work to subagents, run hooks around actions, install plugins, or build custom agents.

The feature names are less important than the problem each mechanism solves.

If an agent repeatedly ignores a repository rule, it needs better project instructions. If it cannot reach an external service, it may need an MCP tool. If the same procedure is repeated across tasks, it may belong in a skill. If a check must always run after an edit, a hook may be the better fit.

In the workshop, I will organize these capabilities into a practical map and use them to build an extension pack around an application. I will also cover the boundaries that come with more capability: permissions, access to local files and remote services, security, tests, diffs, and human review.

Join if you already use a coding agent and want to customize it for the way your project actually works. The goal is to understand which mechanism to choose, how to combine several of them, and how to keep the resulting workflow under control.
