When I get a vague AI engineer take-home assignment, I do not start by coding.

I start by making the assignment less vague.

In the workshop, the task was roughly:

"Build a Telegram bot for investment coaching with safety filtering."

That is not enough to implement well.

So before writing code, I would clarify:

- What is the expected user?
- What kind of questions should the bot answer?
- What should it refuse?
- Which data sources are allowed?
- Are paid APIs acceptable?
- What is the smallest useful version?

For this project, the important decision was not "which framework should I use?"

It was:

Can we build something useful with available public data, while being clear that this is not financial advice?

That led to a narrower product:

An educational investment coach that can explain public company data, summarize signals, and refuse personalized buy/sell/hold advice.

This is what I think good take-home assignments should show.

Not only that you can write code.

But that you can turn an unclear request into a scoped engineering problem.

Especially with AI agents, this matters even more. The agent can generate code quickly. But you still need to decide what problem it is allowed to solve.
