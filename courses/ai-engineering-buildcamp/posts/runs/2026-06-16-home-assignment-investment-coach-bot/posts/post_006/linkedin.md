For an AI engineer take-home assignment, the README is not an afterthought.

It is part of the interview.

In the workshop, we built an investment coaching bot end to end:

- scoped a vague assignment
- chose data sources
- built a CLI agent
- added tests
- added evals
- wrapped it as a Telegram bot
- found limitations

But if a hiring manager opens the repository, they may not read the code first.

They may have only a few minutes.

So the README needs to tell the story.

I would include:

- what the project does
- what the assignment was
- decisions I made
- how to run it
- screenshots or a short demo
- what data sources it uses
- what safety boundaries it has
- what tests exist
- what evals exist
- what monitoring exists
- known limitations
- what I would improve next

I would also be honest about AI-generated code.

It is normal now that candidates use coding agents.

The interesting question is not "did you use AI?"

The interesting question is:

Do you understand what it produced, where it is weak, and how you would improve it?

A polished README helps answer that before the defense interview even starts.
