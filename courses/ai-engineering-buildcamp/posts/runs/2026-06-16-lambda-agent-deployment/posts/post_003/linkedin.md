AI engineers are expected to use coding agents.

They are also expected to understand the code.

This came up directly in the Lambda deployment workshop. A participant asked what the workflow should look like in a real AI engineering role if more and more coding is delegated to agents.

My answer was: the ownership is still yours.

You cannot say:

"The agent implemented it. I have no idea how it works."

A more useful workflow is:

1. Ask the agent to help with the parts where syntax, boilerplate, or platform details slow you down
2. Review what it changed
3. Ask questions about the parts you do not understand
4. Document the final working path
5. Clean up the documentation so you can repeat the process later

This is especially useful for infrastructure work.

The first path may include failed attempts, weird flags, platform-specific details, and small deployment gotchas. If you do not document the path, you only have a working repo and a vague memory.

If you do document it, you get reusable knowledge.

Next time, you can give the document to yourself or to an agent and say: do something similar.
