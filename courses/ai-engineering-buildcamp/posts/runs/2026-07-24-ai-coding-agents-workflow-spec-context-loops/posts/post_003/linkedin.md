Even with coding agents, technology choice is still architecture work.

In the workshop, after scoping the product, I asked the coding agent to propose stack options.

It suggested several paths.

I chose Django.

The reason was not that Django is always the right answer.

The reason was practical:

I know Django well. I can read the code quickly. I have shipped projects with it. I can review the agent's output without spending all my energy decoding the framework.

This matters.

When an agent writes code, you still own:

- The stack
- The operational complexity
- The hosting model
- The dependency choices
- The API choices
- The background job decisions
- The parts you will maintain later

Agents can propose options.

You still need to challenge the proposal.

Ask:

- Is this too heavy for the MVP?
- Do we need this dependency?
- Can we defer this integration?
- Is this version current?
- Can I review and debug this stack?

For AI-assisted development, "let the agent pick" is usually too passive.

The agent can help with architecture decisions.

The architecture is still your responsibility.
