I often start an AI coding project outside the coding agent.

First I use a chat assistant for scoping.

The prompt is simple:

"I want to build this tool. Help me scope the project. Ask me one question at a time and keep your output short."

This does two useful things.

First, it avoids a wall of text. I can answer one decision at a time.

Second, it turns a vague idea into a project spec before code exists.

In the workshop, the original idea was:

"A tool for weekly feedback for projects."

After a short scoping conversation, we had much clearer decisions:

- All team members can contribute feedback
- The format is start/stop/continue
- Feedback is attributed by default, with an anonymous option
- Other submissions are hidden until the right point
- Feedback can be clustered
- Team members vote on what to discuss
- The retrospective produces decisions and action items
- Built-in recording is out of scope for the MVP

This is still not implementation.

It is product work.

But it makes the coding agent much more useful because the agent receives a direction instead of a vague wish.

For me, this is the first part of spec-driven development:

Use AI to help clarify what you want before using AI to build it.
