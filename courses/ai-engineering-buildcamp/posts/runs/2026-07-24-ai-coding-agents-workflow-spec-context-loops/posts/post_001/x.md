1/5

A working agent-built app can still be the wrong app.

In the workshop, I tried a one-shot prompt:

"Implement tool for weekly feedback for projects."

2/5

The agent built a CLI for tracking weekly project health.

Useful, maybe.

But I wanted a team retrospective workflow with feedback cards, anonymity, voting, clustering, and action items.

3/5

The prompt did not contain those product decisions.

So the agent filled the gaps itself.

This is where many AI coding projects drift.

4/5

Before implementation, specify:

Who are the users? What is the workflow? What is in the MVP? What is out of scope? Which decisions should the agent avoid?

5/5

Spec-driven development with coding agents is mostly about reducing ambiguity before code starts.
