# DataTalks.Club Style

Use this reference for DataTalks.Club event promotion. It is separate from Alexey's personal writing style.

## Voice

Write in a practical, community-oriented, technically credible voice. The post should feel useful to people who build data, ML, MLOps, and AI systems.

Prefer:

- Direct openings that start with a problem, question, or useful context.
- Concrete technical language when the source material supports it.
- Clear explanations of what attendees will learn or see.
- Calm confidence.
- Community language that invites participation without pressure.

Avoid:

- Hype-first promotional copy.
- Generic openings such as "Exciting news" or "Join us for an amazing event".
- Corporate slogans.
- Unsupported urgency.
- Over-polished sponsor language that would not sound natural for DataTalks.Club.

## Formatting

Use short paragraphs and make the post easy to scan. Use bullets when listing learning outcomes, agenda items, or distinct reasons to attend.

Keep each post focused on one core angle. If a post needs several paragraphs, each paragraph should advance the argument rather than restate the event details.

## Calls To Action

CTAs should be clear and low-pressure. Prefer:

- Register here: [link]
- Join us: [link]
- Details and registration: [link]
- Save your spot: [link]

Tie the CTA to the post's angle when useful:

- Join us to see how this works in practice.
- Register to follow the live walkthrough.
- Join the session to learn how the speaker approaches this problem.

Do not imply scarcity, exclusivity, certification, discounts, or access limits unless the source material explicitly says so.

## Platform Adaptation

For DataTalks.Club LinkedIn and X, read `datatalks-social-media.md` for account voice and storytelling. Then read `linkedin.md` or `x.md` for platform requirements.

Alexey's personal posts belong to `$social-content-studio`; do not derive his voice from this reference.

If the user does not specify a platform, draft for LinkedIn by default unless the surrounding workflow implies another platform.

## Hashtags And Emojis

Do not add hashtags unless the user asks for them or the source campaign already uses a defined tag.

Use emojis sparingly. They can help mark date, time, or registration in simple event blocks, but the post should not rely on them for energy.

## Factuality

Preserve event dates, times, timezones, speaker names, titles, company names, product names, sponsor names, and registration links exactly as supplied.

If source material conflicts, surface the conflict instead of choosing silently.

If a detail is missing, either omit it or clearly mark it as needed in a brief. Do not fill gaps with plausible assumptions.
